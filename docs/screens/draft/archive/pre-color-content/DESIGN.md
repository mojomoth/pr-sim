# PR-SIM — Design Reference

> 조용한 화면, 실전 같은 발표. Oppie의 흑백 카드 언어를 발표 연습 도구로 확장한다.

**Theme:** light · **Format:** 모바일 우선 웹앱 · **기준 너비:** 390 CSS px · **기본 뷰포트 높이:** 844px, 긴 본문은 스크롤

## Sources & interpretation

- UI 근거: `../refs/`의 Oppie 스크린샷 12장. `01–03`은 중앙 정렬 온보딩과 하단 버튼, `04–05`는 입력에 집중하는 시트, `06–12`는 큰 카드와 흑백 반전, 원형 보조 액션을 보여 준다.
- 구조 근거: `../design/`의 랜딩·상황설정·발표·심사·목록 스케치 및 프로젝트 루트 `CONTEXT.md`.
- 문서 구성 참고: [Refero Styles — Intercom](https://styles.refero.design/style/12255b63-e506-4bc1-a4cd-d05487de32f3). 색상, 서체, 간격, 컴포넌트, 사용 규칙을 토큰으로 설명하는 형식만 참고했다. Intercom의 크림색·보라색·각진 모서리는 채택하지 않았다.
- 브랜드 기준: [확정 브랜드 아이덴티티](../../wiki/brand-identity.md)와 프로젝트 루트 `assets/bi/`. 밝은 화면에는 `assets/bi/lockup-black.png`의 검정 P 심볼·PR·SIM 가로 로고를 사용한다. 이미지 수정에는 배경 포함 동일형 `lockup-light.png`를 참조했다. 기존 STAGE·블루·시안 로고는 사용하지 않는다.

스크린샷에서 관찰한 특징은 흑백 중심 색상, 회색 면, 큰 모서리, 굵은 산세리프, 충분한 여백이다. 아래 HEX·폰트·치수는 원본 CSS를 추출한 값이 아니라 PR-SIM 구현을 위한 제안값이다. 생성 이미지의 세부 표현보다 이 문서의 토큰과 라벨을 구현 기준으로 삼는다.

## Visual language

넓은 흰 바탕 위에 하나의 큰 주제와 하나의 주요 행동을 둔다. 회색 카드는 콘텐츠를 묶고 검은색 버튼은 다음 단계로 이끈다. 발표에서는 슬라이드, 심사에서는 얼굴, 결과에서는 점수가 화면의 중심이 된다. 얼굴 사진은 자연광의 중립적인 실사 이미지를 사용한다. 공격적 페르소나도 과장된 표정 대신 질문 강도와 텍스트로 구분한다.

## Components

### Navigation & actions

모든 화면의 최상단 왼쪽에 확정 검정 P 심볼·PR·SIM 가로 로고를 배치한다. 가로세로 비율을 유지하고 심볼 너비의 1/4 이상 주변 여백을 둔다. 뒤로가기가 같은 줄에 있는 경우 로고 왼쪽에 둔다. 현재 단계·기록·닫기는 기존 헤더 위치를 따른다. 로고에 색상·그라데이션·그림자·윤곽선을 추가하지 않는다. 주요 버튼은 검정 면/흰 글자, 보조 버튼은 회색 면/검정 글자다. 선택하지 않은 행동보다 주요 행동이 먼저 읽혀야 한다. 아이콘만 있는 버튼은 구현 시 접근성 이름을 제공한다.

### Inputs, sliders & uploads

상황은 여러 줄 텍스트 입력이다. 시간은 발표 1–30분, 질의응답 1–20분 범위를 1분 단위로 조절한다. 기본값은 각각 5분과 3분으로 제안한다. 슬라이더 옆에 현재 분값과 감소/증가 버튼을 제공해 드래그 없이도 변경할 수 있게 한다.

PDF는 발표자료(필수)와 제안자료(선택)를 독립적으로 업로드한다. 빈 상태는 업로드 아이콘과 PDF 안내, 완료 상태는 파일명·페이지 수·교체/삭제, 업로드 중은 진행 표시, 실패는 오류와 재시도를 표시한다. 용량 제한은 제품 정책 확정 후 안내한다.

### Judge card

실사 얼굴 썸네일, 이름, 삭제 버튼, `친절함 / 빡셈 / 공격적` 단일 선택 칩으로 구성한다. 선택한 칩은 검정 면이다. `심사위원 추가`로 카드를 추가한다. 시안은 3명 구성 예시이며 한 명당 하나의 페르소나를 가진다. 최대 인원은 제품 정책 확정 사항이다.

### Live session

단계 이름과 남은 시간을 상단에 고정한다. PDF는 원래 비율을 유지하며 좌우 이동 버튼·스와이프·페이지 번호·확대 보기를 제공한다. 발표 화면은 내 카메라, 실시간 음성 전사 말풍선, 심사위원 3명을 함께 보여 준다. 말풍선에는 `음성 인식 중` 또는 `인식 완료` 상태를 표시한다.

질의응답은 발화 중인 심사위원을 큰 얼굴 카드로 보여 주고, 아래에 질문과 내 답변을 서로 다른 면색으로 구분한다. 마이크·카메라 상태와 종료 버튼은 하단에 배치한다. 권한 거부 시 권한 설정 안내와 재시도를 제공한다. 시간이 끝나면 발표→심사, 심사→결과로 전환하되 단계 전환을 명시한다.

### Results & history

종합 결과는 총점, 영역별 점수, 강점, 우선 개선점을 보여 준다. 상세 피드백은 질문별 평가 근거와 답변 개선 예시를 보여 준다. 점수와 조언은 모두 시각 설계를 위한 예시 데이터다. 목록은 날짜·상황·발표/심사 시간·점수·진행 상태를 포함한다. 완료 기록은 결과로, 중단 기록은 이어하기로 연결한다.

## Seven screens

요청에는 7개라고 명시되어 있으나 화면 설명은 6종이다. 결과를 종합 결과와 상세 피드백으로 분리해 7종으로 구성했다. 각 이미지는 서로 다른 경로의 대표 진입 상태를 보여 주는 개별 화면이며, 랜딩 페이지 7가지 변형으로 해석하지 않았다.

| # | File | Content & primary action |
|---|---|---|
| 01 | `01-landing.png` | 타이틀, 흑백 발표장 배경 사진, 시작하기 |
| 02 | `02-setup.png` | 상황, 시간 슬라이더 2개, PDF 업로드 2개, 심사위원 추가·삭제·페르소나 선택, 발표 시작 |

| 04 | `04-review.png` | 질의응답 남은 시간, 큰 심사위원 얼굴, 질문, 내 답변, 답변 완료 |

## Responsive & interaction

모바일은 단일 열이다. 설정 화면은 콘텐츠 길이에 따라 세로로 스크롤하며 CTA만 하단에 고정한다. 데스크톱에서는 최대 1120px 안에서 설정/요약을 2열, 발표 PDF/카메라·전사를 2열로 확장한다. 데스크톱에서도 얼굴과 PDF를 과도하게 확대하거나 늘이지 않는다.

키보드 포커스는 검정 2px 외곽선과 흰 2px 간격으로 표시한다. 음성·영상에 대응하는 텍스트를 유지하고 타이머는 매초 스크린리더로 읽지 않는다. 전환 모션은 180–240ms의 opacity/translate 중심이며 reduced-motion에서는 생략한다. Oppie의 검은 원 확장 효과는 전체 화면 전환 대신 완료 순간의 작은 장식 정도로만 사용한다.

## Do / Don't

- 큰 카드와 넓은 여백, 검은색 주요 행동을 일관되게 쓴다.
- 얼굴·질문·PDF 중 현재 단계의 핵심을 가장 크게 보여 준다.
- 상황·자료·전사를 다음 화면에서도 같은 내용으로 유지한다.
- 페르소나는 반드시 텍스트로 표기한다.
- 무지개 그래프, 강한 그림자, 다중 그라데이션, 작은 글씨로 채운 대시보드는 피한다.
- 흰 배경 위 옅은 회색 본문, 색만으로 구분한 상태, 얼굴 위 긴 문장은 피한다.

## Generation notes

내장 image_gen으로 생성하고 확정 BI 로고로 수정한 검토용 래스터 시안이다. 이전 컬러 로고 버전은 `archive/pre-approved-bi/`에 보관한다. 생성 프롬프트 원문은 `prompts.json`에 기록한다. 생성 결과의 세로 길이는 기본 뷰포트보다 길 수 있으며 전체 구성을 보여 주는 시안으로 해석한다. 한글·아이콘·간격은 생성 특성상 토큰과 미세하게 다를 수 있다. 구현 전 라벨과 상호작용은 위 명세로 확인한다. 사진은 가상 인물이며 평가 내용과 기록은 예시다.
